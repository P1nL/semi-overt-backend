# 01 API 与鉴权

## 为什么读这份文档

这份文档的目标是把“请求是怎么进来的、哪些接口能匿名访问、哪些接口一定要登录、内部服务靠什么传身份”一次说清。它适合在你准备改接口、排鉴权问题、或接入前端时阅读。

## 外部 API 是怎么进来的

当前公网入口统一走 `gateway-service`。

网关职责不是业务处理，而是先做这几件事：

- 拦截所有外部请求
- 识别公开路由与受保护路由
- 尝试解析 JWT
- 统一注入内部身份头
- 把请求路由到对应业务服务

这意味着：

- 业务服务默认不应该再把自己当作公网鉴权入口
- 如果出现“未登录却能访问 protected 接口”或“失效 token 没返回 401”，优先看网关

## 外部 API 路由表

当前固定路由：

- `/api/v1/auth/**` -> `auth-service`
- `/api/v1/users/**` -> `auth-service`
- `/api/v1/home` -> `content-service`
- `/api/v1/categories/**` -> `content-service`
- `/api/v1/articles/**` -> `content-service`
- `/api/v1/reviews/**` -> `review-service`
- `/api/v1/search/**` -> `search-service`
- `/api/v1/uploads/**` -> `file-service`
- `/static/uploads/**` -> `file-service`

## 公开接口、登录接口、管理员接口分别是什么意思

### 公开接口

公开接口指匿名用户可以访问的入口。

它的业务含义是：

- 这些能力面向未登录访客
- 不能依赖当前用户身份才能成立
- 但如果请求里带了非法 token，也不能默默放过

典型公开接口：

- 注册、登录、找回密码、重置密码
- 首页、分类、文章详情、用户主页
- 公开搜索
- 静态资源访问

### 登录接口

登录接口指必须有合法用户身份才能访问。

它的业务含义是：

- 这类能力属于“当前用户自己的操作”
- 重点不只是“有没有登录”，还包括“是不是本人”

典型接口：

- 创建文章
- 保存草稿
- 提交审核
- 取消审核
- 删除文章
- 上传图片

### 管理员接口

管理员接口指即使用户已登录，也只有管理员角色可以使用。

它的业务含义是：

- 这类能力不是“作者视角”的扩展
- 而是系统管理行为，必须和普通用户权限严格分开

典型接口：

- 审核待办列表
- 审核动作

## 无效 token 是怎么处理的

当前无效 token 的判断发生在网关：

- token 缺失：对于受保护路由返回 `401`
- token 黑名单命中：返回 `401`
- token 格式错误或解析失败：返回 `401`
- token 合法但角色不够：返回 `403`

这条规则的意义：

- 业务服务看到的用户身份应该已经是“网关过滤后的结果”
- 下游更适合做细粒度业务授权，而不是重复做公网 token 校验

## 内部头协议

内部头常量统一定义在 [HeaderNames.java](../../common/src/main/java/com/platform/common/constant/HeaderNames.java)。

固定头：

- `X-User-Id`
- `X-Username`
- `X-User-Role`
- `X-Trace-Id`

### 每个头的含义

- `X-User-Id`：告诉下游是谁在发起请求
- `X-Username`：提供用户名信息
- `X-User-Role`：让下游做角色判断
- `X-Trace-Id`：贯穿整条链路的追踪 ID

### 为什么这些头不能由客户端自己传

因为网关会先清掉同名外部头，再重新注入合法值。它的作用是防止客户端伪造内部身份。

## 内部接口为什么存在

内部接口不是对外 API 的复制品，而是服务间协作契约。

典型内部接口：

- `auth-service` 提供用户摘要批量查询
- `content-service` 提供文章审核快照和用户主页文章聚合
- `review-service` 提供最近审核原因和审核任务投影接口

这些接口存在的意义：

- 让真源服务输出标准事实
- 避免服务间直连数据库
- 把跨服务协作固定成可维护契约

## 改 API 时应该先想什么

- 改公开 API：先看网关路由、前端契约和权限边界
- 改登录接口：先看资源归属与本人校验
- 改管理员接口：先看角色判断和特殊业务规则
- 改内部接口：先看真源输出和跨服务兼容性
