## 2. 总体决策建议

1. 当前单体业务语义优先，当前前端不被迫退回旧版接口。路径兼容是 P0，不是收尾项。
2. 保留 gateway/auth/content/review/search/file/notification 七个服务，以及 kernel/web-support/events、三个 contract、migration、architecture-tests 等共 15 个 Maven 模块。
3. 先完成共享 MySQL 下的逻辑微服务兼容版；不同服务限定数据所有权。search 暂时保留显式只读共享查询例外，不宣称已实现独立索引。独立分库/Elasticsearch 另立后续阶段，不混入本次必要范围。
4. content 是文章状态唯一写入者，review 管任务分配和审核命令，auth 管用户与设备会话，notification 管通知。禁止复制单体跨域 JDBC 写入形成第二写入口。
5. 草稿采用数据库持久化 + 显式 CAS。Redis 只作为可失效缓存，不继续以无版本的旧 Redis 草稿 flush 为事实源。
6. 同步短 Access Token + durable device session + rotating Refresh Cookie。旧 Gateway New-Token 自动续期不能绕过新会话撤销。
7. 保留单体用户级首页曝光和草稿不可公开语义。默认不重新引入旧版 30 分钟提审冷却，也不自动引入 OSS/R2 为必需依赖。
8. 代码同步/本地验收与生产切换分成两个里程碑。默认本任务先完成前者，生产切换需单独批准。

公共契约冻结：HTTP status + {code,message,data}、分页字段、null、ID 类型、状态枚举、日期 offset；400/401/403/404/409/429/5xx 分别验证。不要返回 HTTP 200 掩盖应触发刷新或限流的错误。

认证实情：当前 http.ts 使用 withCredentials，401 后最多重试一次，authRuntime 使用跨标签锁和内存 accessToken；不是继续从 localStorage 读取长效 JWT。网络/5xx 刷新失败不等于退出。通过网关验证 Cookie Path/Domain/SameSite/Secure、Set-Cookie 透传、精确 Origin 和 credentials。Cookie 非持久性以是否有 Max-Age/Expires 断言，不能简单把“关浏览器一定清除”作为所有浏览器的保证。

草稿版本补充：单体 SaveDraftRequest.version 可选；省略时服务端仍做本次读取后的 CAS，但不能等同于前端已携带编辑基线版本。现已核实 generated/contracts.ts 的 SaveDraftReqDto 和 editor.mapper.ts 的保存 payload 均不包含 version，保存适配也未返回 version。P0 阶段须新增可选版本字段并贯通详情 DTO、VM、编辑器状态、保存请求和保存响应，配套前端小改，作为明确的同步增强。兼容期间后端不可突然强制该字段，也不能宣称现有前端已完成防陈旧覆盖。

## 5. 状态与事件目标设计

### 5.1 审核唯一决定

建议显式命令状态机，不把远程调用包进本地事务后声称具备分布式原子性：

1. content 提审时 CAS 变为 PENDING，生成 submissionId/递增序号和 articleVersion，同事务写 Outbox。
2. review 幂等建立该次任务，保存 assignedAdminId、submissionId、lastAppliedVersion；排除作者，历史任务按确定规则分配。
3. 决策时 review 条件 claim 任务（分配人、提交代次、未决定），持久化 decisionId/expectedVersion/目标状态，写命令 Outbox。
4. content 消费命令，在同事务内校验文章 PENDING、代次、版本和唯一 decisionId，再更新文章并写 Accepted/Rejected 结果 Outbox。重复命令返回原结果。
5. review 根据结果幂等落最终审核日志/关闭任务；失败命令记录冲突而不伪造成功日志。notification 仅消费已接受的最终结果，唯一键防重复。
6. 取消和删除只能由 content CAS 推进状态；移除旧取消流程中的同步远程删任务，review 接收版本化事件更新投影。旧代次事件不能删除新代次任务。

外部同步接口兼容门槛：当前前端不认识异步处理中。推荐通过有界等待/幂等查询让 decision 接口仅在内容真源确认后返回现有成功结构；超时结果保持可查询/可恢复且不重复提交。若改成 202，必须同时交付前端轮询/处理中状态，不能只改后端。本项在实现前写 ADR 定稿。

### 5.2 Outbox/Inbox

- Outbox 增加 publisher claim/lease/owner、超时恢复、条件更新、confirm/失败重试/DLQ 指标。
- 接受至少一次投递，不承诺绝不重复。消息已发送但未标记成功的崩溃窗口必须由消费者幂等吸收。
- 消费记录和业务副作用尽量同本地事务提交；唯一约束 eventId+consumer、decisionId 或 eventId+recipient/channel 作为兜底。
- 所有投影保存单调版本/提交代次；随机 eventId 只用于去重，不用于排序。
- 故障注入：重复、乱序、延迟、消息发出后进程退出、业务提交后 ack 前退出、消费者重启、双 publisher、DLQ 重放。
- 增加文章 PENDING 无任务、已决定仍有任务、Outbox 长时间未发布的对账任务和修复回执。

## 6. 数据迁移方案

### 6.1 默认策略

先在隔离的新目标数据库导入脱敏快照进行演练，不直接用旧 schema 覆盖生产，也不与现有单体双写同一业务表。初期仍可共享目标 MySQL，但为各服务明确写入权限。

V1 已由 db-migration/pom.xml 复制入 classpath，并非丢失。问题是 DbMigrationApplication baselineOnMigrate(true)/baselineVersion(1)：非空单体库不能靠现有 V1/V2 完成转换。新增显式版本迁移与 schema 前置检查，覆盖空库、旧微服务库、单体导入库三条路径。保留已发布 V1/V2 校验和，禁止改写历史迁移。

### 6.2 表级映射

| 数据 | 目标处理 |
|---|---|
| users | 保留 ID、密码哈希、session_version；统一 password_hash/password 映射，优先扩宽目标，不截断 username/nickname/email/URL |
| auth_device_sessions/auth_refresh_tokens | 先同步目标会话模型再决定是否迁移；保留 persistent、version、到期、撤销、token hash。不能迁移到根本没有目标表的旧认证模型 |
| password_reset_tokens/email_verification_codes | 默认切换时过期作废并提示重新申请；若保留，需验证哈希算法/密钥兼容与消费语义 |
| rate_limit_buckets | 采用等价原子配额存储，跨实例共享；切换窗口不得因为清空计数绕过邮件/上传上限 |
| articles | 保留 ID、状态、软删除、version、提交次数/时间及完整内容；目标 URL/颜色扩宽；draft_visible 保留兼容时强制 false |
| review_tasks | 保留 assigned_admin_id；保留文章关联及待审代次；为缺失历史分配回填，记录无管理员等异常 |
| review_logs | 历史缺 from/to 状态不能猜造；建议兼容 nullable/legacy 标记，保留原 action/reason/operator/time，不丢历史 |
| notifications | 历史缺 biz_id/read/delivery，允许显式 legacy/unknown；不从文案猜业务 ID，不触发历史邮件重发 |
| home_article_exposures | 原样保留用户级数据；不压缩成 last_featured_at |
| event_outbox/event_consume_log | 新 schema 初始化；迁移已有微服务状态时先盘点 backlog，不清空待处理消息 |
| notification_deliveries | 明确 worker 责任；仓库只有 PENDING 记录不等于发信完成 |
| FULLTEXT 索引 | 目标 MySQL 检验 ngram/字符集、索引存在和查询计划后再开 flag；关闭可回退查询 |
| 历史文件 | 保留 URL 和路径清单、抽样 GET；本地 uploads 卷不删除、不搬空；云对象不因切换批量删除 |

预检必需：行数、主键范围、外键孤儿、空值、字段最大长度、重复键、状态合法性、时区/字符集、schema history、用户哈希算法、审核任务与文章状态对账。保留用户/文章 ID，禁止静默截断或重置所有 version/session_version 为 0。

认证切换建议：演练和首次正式切换默认安排重新登录，显式撤销旧会话并保留/递增用户版本，不能“重置为 0”制造旧令牌复活。若要求无感迁移，单独验证单体签名和 claim、刷新 token hash、Cookie 以及撤销信息在目标完全兼容；不额外开一个宽松旧 JWT bridge。

交付脚本：preflight 只读报告、export/import 可重入批处理、schema migration、reconcile、备份恢复演练。输出计数/校验摘要而非账号密码、邮箱或完整正文日志。
