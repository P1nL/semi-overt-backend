# 个人博客系统网站功能演示录制脚本

> 视频只展示网站页面与实际功能，不展示 PPT、项目文档、代码、终端、数据库、Adminer 或 Mailpit。  
> 建议时长：8 分钟左右。  
> 演示主线：公开浏览 → 登录 → 个人主页 → 文章创作 → AI 润色 → 提交审核 → 退回修改 → 再次提交 → 审核通过 → 公开搜索。

## 一、整体演示思路

视频不要按页面机械点一遍，而是围绕一篇文章讲完整故事：

```text
访客浏览网站
  → 作者登录并创建文章
  → 使用 AI 润色正文
  → 保存草稿并提交审核
  → 管理员退回修改
  → 作者根据原因修改并再次提交
  → 管理员审核通过
  → 文章在首页和搜索结果中公开可见
```

这样可以自然覆盖网站的主要功能：

- 首页与文章列表
- 分类浏览
- 文章搜索
- 文章详情阅读
- 登录与身份状态
- 个人主页和草稿箱
- 文章编辑、封面上传和草稿保存
- AI 智能润色
- 文章提交与取消审核状态
- 管理员审核台
- 退回修改、重新提交和审核通过
- 审核后公开搜索

## 二、录制前准备，仅在镜头外完成

### 1. 准备浏览器窗口

- 浏览器窗口 A：作者账号，普通窗口
- 浏览器窗口 B：管理员账号，无痕窗口或另一个浏览器配置
- 两个窗口都提前登录，录制时不展示密码
- 两个窗口都打开网站首页，浏览器缩放保持一致

### 2. 准备演示数据

- 确保首页已有几篇公开文章，便于展示列表和文章详情
- 准备一个普通作者账号和一个管理员账号
- 草稿箱中保留一篇备用草稿
- 审核台中保留一篇备用待审核文章
- 准备一张不包含个人信息的横向封面图
- 标题使用唯一关键词，避免搜索到历史同名文章

推荐文章标题：

```text
从单体到微服务：内容平台拆分实践
```

推荐摘要：

```text
记录内容平台从单体架构拆分为多个业务服务的设计思路与实践过程。
```

推荐正文：

```text
在内容平台拆分过程中，我们没有直接把单体代码按模块复制成多个服务，而是先确定身份、内容、审核、搜索、文件和通知六个业务边界。所有外部请求统一经过网关，再进入对应的业务服务。

文章由内容服务维护主要状态。作者提交文章后，系统生成审核任务；管理员完成审核后，再更新文章状态和公开搜索结果。不同模块各自负责明确的业务范围，减少了相互之间的直接依赖。

这种设计让文章创作、审核和公开阅读能够独立演进，同时保留完整的业务流程。即使某个环节出现短暂延迟，也可以根据文章状态继续追踪和恢复。
```

### 3. 提前彩排

正式录制前完整走一遍以下流程：

1. 作者创建文章并保存草稿。
2. AI 润色能够成功返回。
3. 文章能够提交审核。
4. 管理员能够在审核台找到文章。
5. 文章被退回后能够重新编辑和提交。
6. 审核通过后能够通过标题关键词搜索到文章。

准备备用数据的目的不是伪造流程，而是在某个现场步骤受到网络或异步延迟影响时，可以换一个剪辑点继续录制。

## 三、8 分钟网站功能分镜与口播

### 镜头 1：首页整体展示（0:00～0:35）

**页面操作**

1. 从网站首页开始录制。
2. 鼠标在顶部导航区停留 1 秒。
3. 缓慢向下滚动，展示首页文章列表。
4. 如果主题切换效果稳定，可以切换一次明暗主题后立即切回。

**口播文案**

> 现在看到的是个人博客系统的首页。未登录用户可以直接浏览已经公开的文章，并通过顶部导航进入搜索、分类和文章详情。首页会展示文章标题、摘要、作者和阅读信息，让访客能够快速了解网站中的主要内容。

**建议字幕**

```text
公开首页
文章浏览 · 分类导航 · 全站搜索
```

### 镜头 2：分类浏览（0:35～1:00）

**页面操作**

1. 点击分类入口。
2. 切换一个有数据的分类。
3. 缓慢滚动两到三篇文章。
4. 不要连续快速切换多个空分类。

**口播文案**

> 用户可以按照内容分类浏览文章。切换分类后，页面只展示当前分类下已经公开的内容，继续向下滚动时还可以加载更多文章。这种方式适合用户在没有明确关键词时按照主题发现内容。

**建议字幕**

```text
按分类聚合公开文章
```

### 镜头 3：文章搜索（1:00～1:30）

**页面操作**

1. 点击顶部搜索入口。
2. 输入一个已有文章的关键词。
3. 提交搜索并展示结果数量。
4. 停留在一条结果上，再点击进入文章详情。

**口播文案**

> 除了分类浏览，网站还提供文章搜索。输入关键词后，系统会返回相关的公开文章，并显示搜索结果数量。搜索只面向已经公开的内容，因此草稿、待审核和被退回的文章不会出现在访客的结果中。

**建议字幕**

```text
关键词搜索
只检索公开文章
```

### 镜头 4：文章详情阅读（1:30～2:00）

**页面操作**

1. 打开文章详情页。
2. 展示标题、作者、摘要或正文区域。
3. 缓慢滚动正文。
4. 如果文章存在目录，点击一个目录标题展示定位效果。
5. 返回首页。

**口播文案**

> 进入文章详情后，用户可以阅读完整正文。页面保留清晰的标题层级和阅读区域，较长文章还可以通过目录快速定位。文章详情使用独立的内容视图，打开和关闭时不会打断首页原有的浏览位置。

**建议字幕**

```text
沉浸式文章阅读
正文目录快速定位
```

### 镜头 5：登录与个人主页（2:00～2:35）

**页面操作**

1. 切换到已经登录作者账号的窗口 A。
2. 短暂停留在登录后的顶部头像和操作区。
3. 点击头像进入个人主页。
4. 展示昵称、个人简介、文章列表和写作日历区域。
5. 返回首页。

**口播文案**

> 登录后，顶部区域会切换为当前用户状态。点击头像可以进入个人主页，查看用户资料、公开文章和写作记录。个人主页既是作者管理个人内容的入口，也是访客了解作者和浏览其公开作品的页面。

**建议字幕**

```text
用户登录状态
个人资料 · 公开文章 · 写作记录
```

### 镜头 6：新建文章（2:35～3:30）

**页面操作**

1. 点击新建文章入口。
2. 输入准备好的文章标题。
3. 填写摘要和其他必要信息。
4. 上传准备好的封面图。
5. 将正文一次性粘贴到编辑器。
6. 使用一次标题、列表或引用格式，展示编辑能力。

**口播文案**

> 作者可以在网站中直接创建文章。编辑页面包含标题、摘要、封面和正文区域，正文支持标题、列表、引用、代码块、分隔线和图片等内容结构。这里填写一篇关于内容平台拆分的文章，并上传一张封面图。为了控制演示时间，正文已经提前准备好，现在直接粘贴到编辑器中。

**建议字幕**

```text
文章编辑器
标题 · 摘要 · 封面 · 结构化正文
```

### 镜头 7：AI 智能润色（3:30～4:20）

**页面操作**

1. 点击编辑器左侧的“AI 润色”。
2. 保留约 1 秒加载状态；较长等待后期剪掉。
3. 润色结果出现后，缓慢滚动查看一小段。
4. 鼠标依次指向“重新生成”和“确认应用”。
5. 点击“确认应用”，展示正文发生变化。

**口播文案**

> 编辑器还提供 AI 智能润色功能。点击按钮后，系统会生成一份正文优化建议。结果会先显示在独立的预览气泡中，不会自动覆盖作者正在编辑的内容。作者可以重新生成，也可以确认后再应用。现在点击确认应用，可以看到润色后的文字已经回到编辑器中，之后仍然可以继续修改或撤销。

**建议字幕**

```text
AI 智能润色
先预览，再决定是否应用
```

### 镜头 8：保存草稿与草稿箱（4:20～4:55）

**页面操作**

1. 点击保存草稿。
2. 等待“保存成功”反馈出现并停留 1 秒。
3. 关闭编辑页或返回首页。
4. 点击顶部草稿箱入口。
5. 展示刚保存的文章和当前草稿状态。
6. 再次进入编辑页。

**口播文案**

> 编辑完成后，可以先保存为草稿。保存成功后，即使暂时离开编辑页面，文章内容仍然保留在草稿箱中。草稿箱会集中展示草稿、待审核和被退回修改的文章，方便作者继续处理尚未公开的内容。

**建议字幕**

```text
保存草稿
未公开文章集中管理
```

### 镜头 9：提交审核（4:55～5:25）

**页面操作**

1. 在编辑页点击“发布”。
2. 页面进入二次确认状态后，点击“确认发布”。
3. 等待成功反馈。
4. 返回草稿箱，展示文章状态变为待审核。

**口播文案**

> 确认内容无误后，作者可以提交发布。为了避免误操作，发布按钮需要再次确认。提交成功后，文章不会直接出现在首页，而是先进入待审核状态。作者可以在草稿箱中确认当前处理进度，也可以在审核完成前执行取消审核。

**建议字幕**

```text
二次确认发布
文章进入待审核状态
```

### 镜头 10：管理员退回修改（5:25～6:05）

**页面操作**

1. 切换到管理员窗口 B。
2. 点击“审核台”。
3. 找到刚提交的文章并进入审核页。
4. 快速浏览标题和正文。
5. 点击“退回修改”。
6. 输入：`请补充文章拆分后的实际收益，并优化第二段表达。`
7. 点击“确认退回”，等待成功提示。

**口播文案**

> 接下来切换到管理员视角。管理员可以在审核台查看待审核文章，并根据内容选择通过、退回修改或拒绝。为了展示文章的完整修改流程，这里先选择退回修改，并填写具体原因。提交审核决定后，这篇文章会重新回到作者可以编辑的状态。

**建议字幕**

```text
管理员审核台
退回修改并填写原因
```

### 镜头 11：作者查看原因并重新提交（6:05～6:50）

**页面操作**

1. 切回作者窗口 A。
2. 刷新草稿箱。
3. 展示文章的“已退回”状态。
4. 打开文章，停留在“退回原因”区域。
5. 在正文末尾补充一句内容。
6. 保存后再次点击“发布”和“确认发布”。

推荐补充文字：

```text
拆分完成后，各业务模块可以独立定位问题和调整实现，降低了修改一个功能时影响整条链路的风险。
```

**口播文案**

> 回到作者账号后，可以在草稿箱中看到文章已经被退回。重新进入编辑页，页面会明确展示管理员填写的退回原因。作者根据意见补充内容，保存后再次提交审核。这样，修改要求不会只停留在口头沟通中，而是直接关联到对应文章和审核记录。

**建议字幕**

```text
查看退回原因
修改后再次提交
```

### 镜头 12：管理员审核通过（6:50～7:20）

**页面操作**

1. 切回管理员窗口 B。
2. 刷新审核台并重新打开文章。
3. 点击“通过”。
4. 点击“确认通过”。
5. 等待“文章已通过审核”的提示出现。

**口播文案**

> 管理员再次打开修改后的文章，确认内容符合要求后选择通过。页面使用二次确认避免误操作。审核成功后，文章完成从草稿、待审核、退回修改到最终通过的完整状态流转。

**建议字幕**

```text
确认通过审核
文章进入公开状态
```

### 镜头 13：验证公开结果并结束（7:20～8:00）

**页面操作**

1. 切回作者窗口或未登录的公开窗口。
2. 在顶部搜索框输入唯一关键词“内容平台拆分”。
3. 打开刚审核通过的文章。
4. 返回首页，确认文章出现在公开内容区域。
5. 最后让画面停留在文章详情或首页 3 秒。

**口播文案**

> 最后回到公开页面，搜索刚才文章标题中的关键词。现在可以看到，审核通过的文章已经出现在公开搜索结果中，并且访客可以正常打开阅读。至此，网站已经完成从公开浏览、作者创作、AI 辅助、草稿保存、审核修改到最终发布的完整功能演示。

**结束字幕**

```text
公开浏览 → 内容创作 → AI 润色
→ 提交审核 → 退回修改 → 审核通过 → 公开可见
```

## 四、5 分钟精简版网站演示

如果视频时长只有 5 分钟，删除“退回后再次提交”支线，管理员第一次审核时直接通过：

| 时间 | 网站操作 | 讲解重点 |
|---|---|---|
| 0:00～0:35 | 首页、分类 | 公开文章浏览和分类导航 |
| 0:35～1:05 | 搜索、文章详情 | 关键词搜索和正文阅读 |
| 1:05～1:35 | 登录、个人主页 | 登录状态和个人内容入口 |
| 1:35～2:30 | 新建文章 | 标题、摘要、封面、正文编辑 |
| 2:30～3:15 | AI 润色 | 生成、预览、重新生成、确认应用 |
| 3:15～3:45 | 保存并提交 | 草稿保存和待审核状态 |
| 3:45～4:25 | 管理员通过 | 审核台和权限操作 |
| 4:25～5:00 | 公开搜索 | 搜索到新文章并打开阅读 |

精简版结束口播：

> 通过这次操作，可以看到网站已经覆盖公开浏览、用户登录、文章创作、AI 润色、草稿保存、管理员审核和公开搜索等核心功能。一篇文章只有在审核通过后才会进入公开页面，从而形成完整、清晰的内容发布流程。

## 五、纯网站录制注意事项

### 视频中不要出现

- PPT、Word、Markdown 文档或项目说明文件
- VS Code、IDEA、代码窗口或 Git 状态
- PowerShell、后端日志和服务健康接口
- 数据库管理页面、RabbitMQ、Nacos 或 Mailpit
- API Key、数据库密码、JWT、代理地址等配置
- 真实个人账号、个人邮箱和浏览器自动填充信息

### 页面操作节奏

- 每次进入新页面后停留 1 秒再开始移动鼠标
- 点击按钮后等待成功提示完整出现
- 页面滚动保持匀速，不要来回抖动
- 表单内容尽量提前复制，通过粘贴减少输入时间
- AI 等待时间只保留 1～2 秒，其余部分后期剪掉
- 作者和管理员切换以浏览器窗口为剪辑点
- 搜索和审核状态更新如果存在短暂延迟，等待后再刷新，不要快速连续点击

### 建议的浏览器画面

- 使用 16:9 浏览器窗口并最大化
- 浏览器缩放保持在 90%～100%
- 隐藏书签栏和侧边栏
- 保留网站地址栏可以证明是真实网页；如果画面太拥挤，也可以使用全屏模式
- 鼠标指针使用正常大小，不使用夸张点击特效
- 录制前关闭系统通知和聊天软件弹窗

- [ ] 演示标题不会与历史文章重复
- [ ] 正文和摘要已复制到剪贴板
- [ ] 封面图已放在容易找到的位置

- [ ] 准备了一篇备用草稿和一篇备用待审核文章

- [ ] 没有打开任何代码、终端、文档或管理后台
